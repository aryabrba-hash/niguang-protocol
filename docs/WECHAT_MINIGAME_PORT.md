# 微信小游戏迁移蓝图

## 可直接复用的部分

`src/core/` 不依赖 DOM、浏览器存储或音频接口，可原样进入小游戏构建流程：关卡、随机题序、得分、连击、存档迁移、自适应、每日挑战与本地统计都已有自动测试。

`src/platform/wechat.js` 已提供微信运行时适配层，覆盖本地存档、触感、分享、设备分级和前后台生命周期。迁移时由小游戏入口实例化该适配层，不把 `wx` API 写进核心玩法。

## 仍需替换的部分

- 把 `index.html` 与 DOM 界面重绘为小游戏 Canvas 场景；先保持竖屏单场景，避免首版引入复杂引擎。
- 将 `EffectsController` 的 Canvas 画面保留，将 Web Audio 音效换成 `InnerAudioContext` 或打包音频资源。
- 分享卡片需补 5:4 分享图；排行榜应使用开放数据域，并允许用户不授权继续单机游玩。
- 云存档、排行榜与分析均放到第二阶段；首发版本继续本地优先，避免把登录变成开局门槛。

## 建议目录边界

```text
minigame/
├── game.js                 # 生命周期与场景入口
├── game.json               # 竖屏、分包与网络配置
├── scenes/                 # 首页、训练、结果
├── render/                 # Canvas UI 与特效
└── assets/                 # 本地字体、音频、分享图
src/
├── core/                   # 跨平台玩法，保持纯函数
└── platform/wechat.js      # 微信能力适配
```

## 商业首发顺序

1. 先发布无广告的 20 关 + 每日协议，观察首局完成率、章节完成率、第二日回访和平均训练时长。
2. 首次训练不要求授权；成绩分享由玩家主动触发，不设置强制拉人解锁。
3. 若需要变现，只在完整一局结束后测试激励广告，奖励用于一次“保留连击”或额外训练主题；同一局中不弹插屏。
4. 新增云存档前先给出开关、用途和删除入口，不上传题目级原始行为数据。

## 提审前检查

- 真机覆盖低端 Android、主流 iPhone、刘海屏与弱网/断网。
- 切后台、锁屏、来电后不误扣血；音频与触感尊重玩家设置。
- 分享失败、存储满、无网络时仍能完成训练。
- 包体、启动耗时、内存峰值和帧率写入每次发版记录。
- 明确标注产品是娱乐与认知训练体验，不宣称医疗诊断或治疗效果。
